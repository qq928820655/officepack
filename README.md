# officepack — Office 文档 ⇄ 纯文本 无损装换

把 `doc / docx / xls / xlsx / ppt / pptx`（或任意二进制文件）打包成一段**纯文本**，
之后用这段文本 **100% 还原**出原文件 —— 还原后 SHA-256 与原文件逐字节一致。

```
报表.docx ──打包──> 报表.docx.base91.opk.txt  （纯 ASCII 文本，可加密）
报表.docx.base91.opk.txt ──还原──> 报表.docx   （SHA-256 完全一致）
```

> **不想自己构建？** 直接下打包好的 exe：
> [**Releases · v1.0.0**](https://github.com/qq928820655/officepack/releases/tag/v1.0.0)
> —— 图形界面版（推荐）、单文件便携版、命令行版、应急修复包。

## 为什么不是「提取文字再还原」

Word 二进制（OLE2）和 docx（ZIP+XML）里包含样式表、压缩流、字体嵌入、修订记录、图片。
**把正文抽成纯文本后，这些信息永久丢失，无法还原成原文件。**

所以本工具采用「编码载体」路线：

```
原始字节 → 压缩 → 加密 → 编码成可打印 ASCII → 文本
文本 → 解码 → 解密 → 解压 → 原始字节（SHA-256 校验）
```

正文预览只是**附赠给人看的注释**，不参与还原。

## 快速开始

**免安装，双击即用**（目标机器不需要装 Python，Windows 10/11 64 位）：

| 产物 | 启动速度 | 说明 |
|---|---|---|
| `dist\OfficePack-GUI\OfficePack-GUI.exe` | **1~3 秒** | 图形界面，支持拖拽，**推荐**（从同目录 `启动.bat` 进，会先自检） |
| `dist\OfficePack-GUI-win64.zip` | — | 整个 GUI 目录的压缩包，**换电脑时传这个** |
| `dist\officepack\officepack.exe` | **0.5 秒** | 命令行版 |
| `dist\OfficePack-GUI-便携单文件（启动慢）.exe` | 45 秒 | 只有这一个文件，拷走即用；功能与目录版一致 |
| `dist\officepack-便携单文件（启动慢）.exe` | 25~45 秒 | 命令行版单文件；**不含本轮新增的 `--no-split` / `unpack -`**，需要这两个请用目录版 |

目录版是绿色软件：把整个文件夹拷走就能用，删掉即卸载。
单文件版每次启动都要把 17MB 运行时解压到临时目录，**实测 20~45 秒**（被杀软反复扫描时更慢），
只适合「必须只发一个文件」的场合。日常使用请用目录版。

## 迁移到另一台电脑

目录版是 **1122 个文件**（其中 `_internal` 里 1121 个，几乎全是 Tcl/Tk 脚本和 Python 运行时）。
逐个文件拷贝极易丢文件，**必须整包传输**：

| 传什么 | 大小 | 用法 |
|---|---|---|
| `dist\OfficePack-GUI-win64.zip` | 16.7 MB | **首选**。传过去解压，得到 `OfficePack-GUI` 文件夹，双击里面的 `启动.bat` |
| `dist\修复包-_tk_data.zip` | 269 KB | **应急**。只补 `_internal\_tk_data` 一个目录，解压到 `OfficePack-GUI` 目录下覆盖 |

### 报错 `Tk data directory "..._internal\_tk_data" not found`

这是**丢文件**，不是程序 bug（`_internal\_tk_data` 里有 89 个 Tcl/Tk 文件，缺了整个界面库就起不来）。

修复顺序：

1. **应急**：解压 `修复包-_tk_data.zip` 到 `OfficePack-GUI` 目录（覆盖），再双击 `启动.bat`
2. **彻底**：删掉旧文件夹，重新解压 `OfficePack-GUI-win64.zip`
3. 之后**都从 `启动.bat` 进**，它会先检查 6 个关键文件，缺了直接告诉你缺哪个

### 判断是不是安全软件在删

打开 `_internal` 看两个目录：

- `_tcl_data` 在、`_tk_data` 不在 → **传输丢了一个子目录**，重新整包传即可
- 两个都不在（或 `.tcl` 文件被清零）→ **安全软件按扩展名在删**，需联系 IT 加白名单；这种情况下压缩包解压后也会被删，建议改用单文件版

**图形界面用法**：拖入文件 → 选预设和口令 → 点「开始处理」。

- 处理中按钮显示「处理中…」，进度条实时推进
- **完成后弹窗汇总成功/失败数量，并显示输出文件夹的完整路径**，可直接点「是」打开该文件夹
- 有失败时弹窗给出每个文件的失败原因（如口令错误、文件被占用）
- 右侧常驻「打开输出文件夹」按钮，事后也能一键定位产物
- 输出目录留空时，产物保存在**源文件所在目录**
- **「分片输出」默认不勾**，需要切段时才勾上并填每段字符数
- **「粘贴文本还原…」**：不存文件也能还原，多个分片可粘进同一个文本框
- **每个参数名后面的蓝色 `?`** 点开就是该项说明（每个选项的差别、当前选中项高亮）；底部「全部参数说明…」可一次看完

命令行（在 `dist\officepack\` 里）：

```bash
# 打包（字符数最少 + AES-256-GCM 加密）
officepack.exe pack 报表.docx --preset chars --password 123456

# 校验（只验证能否完整还原，不写文件）
officepack.exe verify 报表.docx.cjk.opk.txt --password 123456

# 查看元信息
officepack.exe inspect 报表.docx.cjk.opk.txt

# 还原
officepack.exe unpack 报表.docx.cjk.opk.txt -o 输出目录 --password 123456
```

源码方式运行（开发调试用）：`python -m officepack <子命令>`，或双击 `officepack.cmd`。

## 配置怎么选（速查）

图形界面里每个参数名后面都有个蓝色 **?**，点一下就能看到「这个参数是干什么的、每个选项差别在哪」，
当前选中的选项会带 ▶ 标记；右侧底部「全部参数说明…」可以一次看完。

| 你的实际限制 | 怎么配 | 为什么 |
|---|---|---|
| 每次只能输入 N 个**字** | 预设 `chars`，需要时勾「分片输出」填 N | cjk 一个汉字装 14 bit，字符数最少 |
| 按**字节**限额（邮件、短信、接口） | 预设 `compact` | base91 是纯 ASCII 里最紧凑的，字符数少且每字符 1 字节 |
| 粘贴后可能被改大小写 / 插转义符 | 预设 `safe` | 纯大写字母+数字，没有任何符号可被破坏 |
| 文件很小、要人工核对 | 预设 `plain` | 不压缩，肉眼能看出是 base64 |
| 不想让别人看到内容 | 加密器 `aes-256-gcm` + 填口令 | 同时防篡改，改 1 个字符就解不开 |
| 内容是 jpg / png / zip 这类已压缩文件 | 压缩器 `auto` 或 `none` | 再压没有收益，`auto` 会自动跳过，不会越压越大 |
| 文档里全是重复的中文条款 | 压缩器 `max` | 多组 lzma 参数逐个试，压得最狠（但最慢） |

## 预设

| 预设 | 编码器 | 压缩 | 说明 |
|---|---|---|---|
| `chars` | cjk | max | **字符数最少**，冲万字级目标用这个 |
| `compact` | base91 | auto | ASCII 体积最小 |
| `safe` | base32 | auto | 纯大写字母+数字，邮件/IM/Excel 粘贴不会被转义 |
| `fast` | base64 | zlib | 速度优先 |
| `plain` | base64 | none | 不压缩，最透明 |
| `自定义` | 手动 | 手动 | 改下面任意一项，预设会自动变成「自定义」 |

## 编码器与压缩器

编码器（膨胀率 = 文本字符数 / 原始字节数）：

| 编码器 | 字符/字节 | 特点 |
|---|---|---|
| `cjk` | **0.571×** | 汉字编码（每 14 bit 一个汉字），**字符数最少**，比 base91 再少 54% |
| `base91` | 1.231× | ASCII 下最紧凑，字母表已排除 `-` `'` `\` |
| `base85` | 1.250× | 紧凑，但含 `"` `'` `\`，部分渠道会转义 |
| `base64` | 1.334× | 最通用 |
| `base32` | 1.600× | 纯大写+数字，最耐复制粘贴 |
| `hex` | 2.000× | 最直观可审计 |
| `custom` | 1.334× | 自定义 64 字符码表（`--alphabet`），带码表置换 |

压缩器：`max`（多组 lzma 参数逐个试，取最小）/ `auto`（试 lzma，无收益自动跳过）/ `lzma` / `zlib` / `bz2` / `none`。

## 万字级目标与分段

> 下面的示例用 `python -m officepack` 表示命令；如果你用的是 exe，换成 `dist\officepack\officepack.exe`。

```bash
# 默认整份输出，不分片
python -m officepack pack 报告.docx --preset chars

# 目标：整份文档的文本总量压到 1 万字以内
python -m officepack pack 报告.docx --preset chars --target 10000

# 需要切段时才显式开启：每段最多 1 万字
python -m officepack pack 报告.docx --preset chars --split 10000 --password 123456

# 强制整份输出，覆盖已有的分段设置
python -m officepack pack 报告.docx --preset chars --split 10000 --no-split
```

**是否分片是显式开关**：

| 场景 | 做法 |
|---|---|
| 不分片（默认） | 什么都不加；或加 `--no-split` 强制覆盖 |
| 按字符数切 | `--split N` |
| 切成固定段数 | `--parts K` |

图形界面里对应右侧的「分片输出」复选框：**默认不勾**，勾选后才能填「字/段」，切到还原模式时自动置灰。

**1 万字能装多少，取决于文档的信息量**（1 个汉字承载 14 bit，1 万字 ≈ 17.5KB 不可压缩数据）：

| 文档类型 | 原始大小 | 结果 |
|---|---|---|
| 纯中文正文 4,000 条 | 311 KB | ✓ 1,120 字 |
| 高度重复文本 | 630 KB | ✓ 131 字 |
| 随机二进制 | 8 KB | ✓ 4,572 字 |
| 随机二进制 | 17.5 KB | ✓ 10,000 字（正好上限） |
| 随机二进制 | 50 KB | ✗ 需 28,572 字 = 2.9 段 |
| 含 500KB 图片的 docx | 500 KB | ✗ 需 28.6 段 |

**结论**：纯文字类文档几乎都能进 1 万字；含图片/嵌入对象的文档，图片本身已是压缩格式，无损还原下无法再压，只能分段。

分段格式（每段可独立发送，乱序收集也能拼回）：

```
#OPK1 cae6c6 003/012 l).)@ 9282
<该段载荷，每行 100 字符>
```

头部字段：文档 ID / 序号 / 总段数 / 段 CRC32 / 段字符数。
最后一位让解析器精确截断——**段尾多粘了无关文字会被自动忽略**，不会破坏校验。

还原时把全部段一起传入即可（顺序随意）：

```bash
# 从文件还原，分片可一次给多个
python -m officepack unpack part*.txt --password 123456

# 不用存文件：把分片文本从管道喂进去
type part*.txt | officepack.exe unpack - --password 123456
```

**手动输入文本还原**：图形界面右侧有 **「粘贴文本还原…」** 按钮，把容器文本直接粘进文本框即可，
不用先存成文件。支持三种形态：

- 一整个完整容器
- 单个分片
- **多个分片全粘在同一个文本框里**，顺序随意，段与段之间夹说明文字也不影响

对话框里有「检查分片」，会实时显示 `共 24 段，已收 5 段，缺第 6、7、8…段`，
凑齐了再点「还原」，避免白试一次。

缺段、重复段、单段被改动，都会明确报错并指出是第几段。

实测（含 1.5MB 图片的 docx，1,500,594 字节）：

| 方案 | 文本体积 |
|---|---|
| base32 + zlib | 2,426,278 B |
| base64 + zlib | 2,022,016 B |
| base85 + lzma | 1,895,329 B |
| **base91 + auto** | **1,864,514 B**（比 base32 省 23%） |

未压缩的文本型 doc（1,260,000 字节）：`base32+zlib` → 5,659 B，`base91+auto` → **1,066 B**（省 81%）。

## 文本容器格式

```
-----BEGIN OFFICEPACK v1-----
Meta: eyJ2IjoxLCJuYW1lIjoi...          ← base64(JSON)：文件名/大小/SHA-256/算法参数
Info: 报表.docx | 48213 B | text=59187 chars | codec=base91 | compress=lzma | cipher=aes-256-gcm
Preview:                                ← 人可读正文预览（不参与还原，可用 --no-preview 关闭）
  | 第一章 总述
Payload:                                ← 纯 ASCII 载荷，每行 100 字符
MZXW6YTBOI...
-----END OFFICEPACK v1-----
```

还原只依赖 `Meta` + `Payload`，`Info` / `Preview` / 注释行全部忽略，
所以文本可以随意加前后缀、被邮件折行、被 IM 截断后拼接回来。

`--ascii-only` 可让整个文件严格 7-bit ASCII（注释区中文转 `\uXXXX`）。

## 安全

- **AES-256-GCM**，密钥由口令经 **scrypt**(n=16384, r=8, p=1) 派生
- 每块独立 nonce（8B 随机前缀 + 4B 计数器），分块 1 MiB，内存占用与文件大小无关
- AAD 绑定原始大小与 SHA-256 → 元信息被改动会导致解密直接失败
- 任意一位翻转都会触发 GCM 认证失败或 SHA-256 校验失败

## 限制

- 老格式 `doc / xls / ppt` 不生成文字预览（无法解析 OLE2），但**无损还原完全支持**
- `cjk` 编码器字符数最少，但 UTF-8 字节数约为原始的 1.71 倍——只适合「按字符数限制」的渠道；
  若渠道限制的是字节数，请用 `base91`
- 打包需全量读入内存，峰值约为文件大小的 3~4 倍；几十 MB 的文档无压力
- 依赖 `cryptography`（仅加密时需要），未安装时可用 `--cipher none`

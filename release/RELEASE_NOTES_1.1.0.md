# OfficePack v1.1.0

新增**二维码通道**：除了文本，还能把文件做成二维码图片，走扫码工具跨网传输，或者截图再扫回来。
另外修掉了高缩放屏幕下界面底部按钮被裁的问题。

## 新功能：二维码

```bash
# 打包成二维码，一张放不下会自动拆帧
officepack pack 报告.docx --qr

# 从截图/图片还原
officepack unpack 截图.png
officepack unpack 图片目录
```

图形界面：右侧新增「输出二维码 → 生成图片」勾选框，以及「截图还原（二维码）…」按钮
（优先读剪贴板截图，直接 `Win+Shift+S` 截图后点它就行）。

**设计要点**

- 载荷固定 `base32`（`A-Z` + `2-7`），正好命中二维码的**字母数字模式**，1 字节只花 1.6 字符。
  换成 base64（含小写）会掉回字节模式，容量反而更小。
- 每帧就是一个自包含的 `#OPK1` 分段，和文本分片**完全同一套格式**，
  所以还原走的还是 `unpack_texts()`，没有第二套合并逻辑。
- 分帧按**比特**预算算，不按字符数：段头与 Meta 行含 `#` `:` 等符号只能走字节模式（8 bit/字符），
  光数字符会在首帧悄悄超容量（第一版就是这么炸的）。
- 帧数 ≤ 12 时额外生成 `*.qr-all.png` 总览图，**截一次屏带回全部帧**；
  超过 12 不拼 —— 实测 125 帧的总览图（11700×11000）会丢帧。

**容量**（QR v40，字母数字模式）

| 纠错 | 字符容量 | 净装数据 |
|---|---|---|
| L | 4,296 | ≈2.5 KB |
| M | 3,391 | ≈2.0 KB |
| Q | 2,420 | ≈1.4 KB |
| H | 1,852 | ≈1.1 KB |

实测：1.4 KB docx → 1 张；16 KB 随机数据 → 5 张；60 KB 随机数据 + AES 加密 → 24 张。

## 修复：界面底部按钮被裁

**现象**：125%/150% 缩放的机器上打开界面，「开始处理」下面三个按钮看不见。

**根因**：`geometry` 写死 `980x660`。Tk 的像素是物理像素，字体却随系统缩放放大，
本机实测内容需要 `797x942`，右栏自身要 667px 却被分到 578px，多出的部分被窗口边缘直接裁掉。

**修复**：

- 删掉写死的尺寸，布局建完后按 `winfo_reqwidth/reqheight` 实测内容，再钳制到**工作区**
  （`SPI_GETWORKAREA`，扣掉任务栏；只减常数在任务栏高一点时会把窗口压到任务栏下面）
- 右栏改为可滚动画布：装得下就完整显示、滚动条隐藏；装不下才出滚动条 —— 小屏也能滚到底
- 空间不足时优先压缩日志框行数（6 → 2）
- `minsize` 直接用算出来的尺寸，避免手动缩小又把控件裁掉
- 对话框同样按工作区钳制并居中

验证矩阵（全部通过）：125%/1536×920、125%/1280×680、150%/1920×1000、100%/1024×700、125%/1366×768。

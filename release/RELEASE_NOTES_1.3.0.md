# v1.3.0 — 单张码多装 20%，动图与框选还原

## 一句话

二维码通道全面优化：**单张码从 2077 字节提到 2357 字节**（+13%），新增 **GIF 动图**和
**框选屏幕还原**，多帧容错从「报错」变成「自动挑选好帧」。

---

## 二维码：重新压榨每一字节

上一版单张码只能装 2.0 KB，因为它做了三件浪费空间的事。这版全修了：

| 优化 | 手段 | 收益 |
|---|---|---|
| 换编码器 | 新增 `qr45`（2 字节 → 3 字符，字符集就是 QR 字母数字模式的 44 个符号） | +6.7% |
| 压缩元信息 | Meta 行 zlib 后 base64（前缀 `~` 区分，老文本仍可读） | 首帧少占 280 字符 |
| 精确比特预算 | 按编码器实际位宽算帧容量（5.5 / 8.0 / 24.0 bit） | 不再保守留白 |

实测单张上限（QR 40 版、纠错 L、压不动的随机数据）：

| 组合 | 单张最大 |
|---|---|
| `qr45` + 不加密 | **2,495 字节** |
| `qr45` + AES-256-GCM | **2,357 字节** |
| `base32` + AES（v1.2 口径） | 2,077 字节 |

> 物理上限就是 4,296 字符 × 5.5 bit ÷ 8 = 2,953 字节，谁都突破不了。
> 想「一张搞定」就得让**压缩后**的体积落进 2.4 KB —— 源码/Markdown 约 8~12 KB 原文件，
> docx/zip/pdf 本身已压缩，只有 2 KB 出头的小文档能单码。

新增预设 **`qr`（qr45 + lzma max）**，出码一律选它。用默认的 `cjk` 出码会多出 **4.7 倍**帧数。

## 静态 / 动态，随便选

二维码输出格式变成三选一：

| 格式 | 适合 | 怎么读 |
|---|---|---|
| **PNG 单帧 + 总览图** | 电脑上还原 | 总览图一张含多码，一次识别全部 |
| **GIF 动图** | 手机对着屏幕扫 | 循环播放，相机逐帧抓 |
| **PNG + GIF** | 两端都要 | 两套都出 |

GIF 对二维码是**像素级无损**（只有黑白两色，2 色调色板 + LZW，
`test_gif_is_pixel_lossless` 逐字节比对了像素）。但体积不会比 PNG 小——
每帧图案完全不同，GIF 的帧间压缩用不上（4 帧：PNG 69KB / 总览 72KB / GIF 131KB）。

**想压体积就降分辨率**：识别看的是「每模块几个像素」，3 px 就够（v40 是 185 模块，
555 px 即可），不必 5 px。`--qr-px 600` 省 30%~40%，识别率不受影响。

GIF 也能直接当输入：`unpack` 会**逐帧**识别，把一个 `.gif` 丢进去就还原。

## 框选屏幕还原

GUI 的按钮升级成下拉菜单：

- **框选屏幕区域**（新增）— 全屏半透明遮罩，拖框圈住码，松开即识别还原，省掉「截图存文件再选文件」两步
- 读取剪贴板截图
- 选择图片文件

已处理 DPI：启动时 `SetProcessDpiAwareness(2)`，150% 缩放下框选坐标不再错位。

## 多帧容错：从「报错」改成「自动挑好的」

| 场景 | 以前 | 现在 |
|---|---|---|
| 同一张码扫了两遍 | 报「第 N 段重复出现」 | 自动忽略 |
| 一张扫糊 + 一张清晰 | 报「校验失败」 | 用清晰的那张 |
| 缺一帧 | 只说「缺少第 3 段」 | 补一句「另有第 5 段校验失败，重扫这几张」 |
| 同序号两份**不同**内容 | 报重复 | 仍报错（绝不瞎猜） |

另外总览图改成**分页**（每页 12 帧，多页自动续）：19 帧以前干脆不拼图，
现在给你 2 张图，截两次屏就全覆盖。

## 已知边界

- 单张码 2.4 KB 是 QR 标准的硬上限，不是实现问题
- GIF 体积 ≈ PNG，不省空间；省空间靠降分辨率
- 框选屏幕只框当前主屏（多屏需先移窗口）

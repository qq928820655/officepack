# v1.4.0 — 多屏框选、屏幕水印净化、粘贴识别面板

## 一句话

二维码还原这条路彻底打通：**哪块屏幕都能框**、**屏幕上叠着水印也能认**、
**多张截图能累积**、**多选图片不再只认最后一张**。

## 新增

### 1. 框选支持多屏

以前遮罩只铺主屏（`winfo_screenwidth` 只有主屏尺寸），副屏上根本点不到框。
现在按**鼠标所在的那块屏**铺遮罩：`GetCursorPos` + `MonitorFromPoint` 拿到该屏在
虚拟桌面里的矩形，再用 `SetWindowPos` 精确定位。副屏在主屏左边、坐标是负的也照常工作。

### 2. 屏幕 / 软件水印净化

针对的是「图片文件本身干净，但显示在屏幕上/看图软件里时被叠了水印」这种场景：
企业屏幕监控水印、预览软件角标、远程桌面会话标记。截图会把这层一起截进去。

识别不再只跑一次原图，而是自动做一轮像素级净化，从便宜往下试、收全就停，单图总预算 6 秒：

| 顺序 | 处理 | 针对 |
|---|---|---|
| 1 | 固定阈值二值化 ×4 档 | 半透明浅灰水印（码是纯黑，低阈值把不够黑的漂白） |
| 2 | Otsu 自适应 | 整体偏亮/偏暗、压缩噪点 |
| 3 | 反色 | 深底浅码 |
| 4 | R/G/B 单通道 | 彩色水印 |
| 5 | 2×/3× 放大 | 码在屏幕上被缩得很小 |
| 6 | 中值滤波 | 细线水印 |
| 7 | 重叠切块 2×2 | 局部遮挡 |

实测（6 帧总览 + 满幅水印 + JPEG + 缩放，括号内为只跑原图）：

| 场景 | 原图 | 净化后 |
|---|---|---|
| 缩放 35% | 5/6 | **6/6** |
| 缩放 30% | 1/6 | **6/6** |
| 缩放 28% | 1/6 | **5/6** |
| 0.8 不透明度灰字铺满 | 3/6 | **6/6** |

28% 以下属于分辨率物理极限（每模块只剩 1 px），会明确提示「放大到 100% 再截」。

### 3. 粘贴识别面板（新还原方式）

`还原二维码 ▾ → 粘贴识别面板…`：

- 在面板里 `Ctrl+V` 贴图，**可反复多次**，识别到的帧自动累积
- 底部实时显示「共 N 帧，已收 M 帧，缺第 X 帧」
- 「读剪贴板」：直接读剪贴板里的图 / 文件 / 文本
- 「打开 Ditto 剪贴板」：见下
- 文本区也能直接粘容器文本、分片，一栏搞定

### 4. Ditto 剪贴板兼容

- 剪贴板读取不再依赖 Pillow 的 `grabclipboard()`（只认最前面一项，Ditto 的 CF_DIB 常读不到），
  改为直接调 Win32 API 依次尝试 `PNG / CF_DIBV5 / CF_DIB / CF_BITMAP / CF_HDROP / 文本`
- `Ditto.exe` **自动探测**，不写死路径：运行中的进程 → 卸载注册表 → PATH →
  环境变量与各本地盘符的常见目录（网络盘/光驱跳过，避免卡住）
- 点「打开 Ditto 剪贴板」把历史窗口叫出来，在里面双击要用的图，Ditto 会把图贴进面板，
  自动识别累积 —— 等于「Ditto 里多选多张图，逐张喂给面板」
- 没装 Ditto 走兜底：`Win+Shift+S` 截图 → 面板 `Ctrl+V`

### 5. 多选图片不再只认最后一张（真 bug）

两个入口都有问题，已修：

- `ct.unpack_sources()` 拿到 PNG 会直接 `open(..., "r")`，抛 `UnicodeDecodeError`；
  现在按扩展名分流，图片自动交给扫码器
- 界面主流程还原改为统一走 `qr.unpack_any()`，图片 / 文本 / 混着给都能一起还原

多图**顺序错乱、重复、跨总览页**都能正确合并（本来就按段头序号重组，现在有测试锁死）。

### 6. 只出总览图

`--no-single`（GUI 里选 `PNG（仅总览）`）：总览里每张码是**原尺寸拼贴、没有缩放**，
和单帧图信息量完全相同，识别总览就等于识别全部单帧，少写 N 个文件。
只有 1 帧时没有总览可拼，会自动回退成单帧输出。

## 修复

- `container.unpack_sources()` 吃图片崩溃（UnicodeDecodeError）
- 界面「选择图片文件」多选后只还原出最后一个文件
- 剪贴板里是 Ditto 的 CF_DIB 时读不到图
- 副屏上框选无反应
- 总览图跨页时白跑 6 秒重试（现在识别到 ≥2 帧且净化无新增就直接收工）

## 升级

版本 1.3.0 → 1.4.0。**容器格式没变**，v1.1 / v1.2 / v1.3 生成的文本和二维码都能照常还原。

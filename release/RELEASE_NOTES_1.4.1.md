# v1.4.1 — 框选连拍收动图 + GIF 首尾标识帧

> 一句话：**屏幕上播着动图，拖个框就等它自己收全。**
> 顺带修掉一个真 bug —— 旧版 GIF 的某些帧会被裁掉右下角，播放器里显示的是残缺码。

## 1. 框选不再是「截一张」，而是「连拍」

一张截图只能拿到动图播放中的**某一帧**，靠单次截图收全十几帧本来就是不可能的。
现在拖框松手后对着这块区域连续抓图：

- 静态码：第一枪就齐，**立即返回**（不干等）
- 动图：一直拍到收齐，或连续两轮没有新帧才收工
- 画面没变化就跳过解码（指纹去重），所以采样能追上 3 帧/秒的播放速度
- 漏的帧**再框一次自动续上**：已收的攒着，不重复、不用从头来
- 抓图前会等一帧让半透明遮罩真正消失，避免把 30% 的灰一起截进去

实测（7 帧 + 3 帧/秒播放 + 真实屏幕）：**2.4 秒收全 7/7，还原逐字节一致**。

## 2. GIF 加首帧 / 尾帧标识

生成的动图现在首尾各有一张标识帧：

```
#OPKmark|S|<文档ID>|<总帧数>     ← 首帧
#OPKmark|E|<文档ID>              ← 尾帧
```

识别端因此**不用猜播放相位**：见 S 认为一轮开始，见 E 认为一轮结束，收齐就停；
某轮漏了帧就自动再等下一轮。旧动图（没有标识帧）照旧能用，退化成
「连续 3 秒没有新帧就收工」。

还原路径会自动滤掉标识帧 —— 它只是控制信号，不会混进数据。

## 3. 真 bug：GIF 帧尺寸不一致导致裁边

每帧的数据量不同 → QR 版本不同 → 按目标像素反推的模块大小一取整，
产出的图片尺寸就参差不齐（实测 555 px 和 665 px 混在一起）。而 GIF 的逻辑画布
取的是**首帧尺寸**，比画布大的帧会被裁掉右/下边 —— 播放器里就是个残缺码，
扫不出来，框选自然也永远收不齐。

现在所有帧统一成同一像素尺寸（按最大的那帧算模块大小、其余居中补白）。
新增测试 `test_gif_frames_share_one_canvas` 锁死这条。

## 4. 框选遮罩铺满所有屏幕

上一版按「鼠标所在的那块屏」铺遮罩，双屏时另一块屏不暗、点上去也没反应，
看着像功能坏了。现在按 Windows 虚拟桌面尺寸铺满所有显示器，拖框可以跨屏；
进程 DPI 感知升级到 `PER_MONITOR_AWARE_V2`，主屏 125% + 副屏 100% 的混合缩放
也不会错位（`test_overlay_window_covers_all_monitors` 用 `GetWindowRect` 实测坐标）。

## 5. 顺手

- 每块屏幕顶部各显示一条操作提示（双屏不用来回找提示在哪）
- 右键 / Esc 取消框选
- 框错地方时快速失败（连开几枪没码就转单张全力重试），失败弹窗给出具体做法
- 二维码内容超出纠错级别容量时，报「请降低纠错级别 / 调小每帧字符数」而不是
  `Invalid version (was 41)`

## 验证

- **117 项单测**全绿（新增 10 项：连拍收全、首尾标识、帧尺寸统一、多屏遮罩、主线程回调）
- 产物级验证 10 项通过（直接跑 dist 里的 exe）

## 升级建议

**旧版 GIF 建议重新生成**：老动图可能存在被裁边的帧，怎么扫都收不全。
用本版重新打包一次即可。

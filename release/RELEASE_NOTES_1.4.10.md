# OfficePack 1.4.10 — 「进度看不见」全清掉，打包链路提速 3~4 倍

这一版只解决一件事：**该动的地方不动，该快的地方不快**。

你给的两张截图，暴露的是同一类问题的三个不同现场：

| 现场 | 现象 | 真凶 |
|---|---|---|
| 刚点「开始处理」 | 「压缩加密 0%」挂 60 秒 | `max` 档**全量试 4 组 lzma**，且全程不回调 → 16.5MB 实测 **34.6 秒**，压完还因为「没省下来」全部丢弃 |
| 渲染矩阵前 | 「0%」再挂一分钟 | zxing 预排要逐帧编码 3825 张码，`_plan_zx` 是个纯静默循环 |
| WebP 收尾 | 「写入 WebP 100%」之后还要等 30~40 秒 | PIL 的 `save_all` 一次性写完，进度直接跳到 100%；心跳又把「还要几十秒」的提示覆盖成「100%」 |

---

## 一、压缩：先花 0.2 秒判断「压不压得动」

已压缩格式（rar/zip/7z/docx/mp4/jpg）再压，熵已经饱和 —— 压缩率 100%，纯烧 CPU。

实测 16.5MB 随机数据（≈ rar）：

```
旧：max = 4 组 lzma 各 8.3 秒 = 34.6 秒，最后判定「没省」全部丢弃
新：256KB 采样 ≈ 0.13 秒，判定「压不动」直接原样打包
```

对**真能压**的数据，`max` 也不再全量试 4 组，而是「在 256KB 采样上比出最优参数组 → 按这组压一次全量」：

```
9MB 文本：旧 2.09 秒（4 组）→ 新 0.71 秒（采样选参 + 1 次全量），压缩率完全相同
```

压缩精度没有任何损失：采样选出来的参数组和全量选出来的是同一组（实测同为 `lc0pb0`）。

## 二、编码只做一次

`pack_bytes` 算过一次 `qr45` 编码，`build_frames` / `render` / `split_pack` 又各算一次 ——
16.5MB 每多做一遍就是 **5 秒**。现在编码结果随 `PackResult` 一起带走，下游直接复用。

## 三、WebP 写入：自己拼容器，逐帧并行

PIL 的 `save_all=True` 走 libwebp 的 `WebPAnimEncoder`：一次性写完，拿不到进度，也吃不满多核。

现在改成「逐帧独立编码（并行）→ 自己拼 RIFF/VP8X/ANIM/ANMF 容器」：

| | 旧 | 新 |
|---|---|---|
| 957 帧写 WebP | 40~85 秒 | **6~7 秒** |
| 进度 | 一次跳到 100%，之后干等 | 每帧一次，1/957 → 957/957 |
| 内存 | 全部帧铺在内存里 | 只留「在飞的」几帧 |

libwebp 编码时释放 GIL，实测 8 线程 **6.5 倍**加速（42.4 ms/帧 → 6.5 ms/帧）。

成品格式是标准 WebP 动画，PIL 读回来逐帧像素比对**完全一致**，浏览器/看图工具照常播。

## 四、全链路进度：六个阶段各有各的百分比

现在一条打包链路会连续报：

```
压缩 0→70%  →  加密 70→77%  →  编码 77→100%  →  排版 0→100%  →  渲染 0→100%  →  写入 0→100%
```

内部刻度（0~1000）只用于换算，界面上只显示百分比，不会出现「350/1000」这种内部数字。
换阶段时日志的「每 10% 一行」会重新计数 —— 事后翻日志能看出每一步花了多久。

## 五、三个附带修掉的 bug

1. **心跳把「还要几十秒」覆盖成 100%**。`_bar_heartbeat` 每秒拿 `done/total` 重写文案，
   正好盖掉「写入 GIF…已 30s，大约还要 20 秒」。现在一次性写入阶段走动画条 + 估时文案，
   心跳只更新已用秒数。
2. **工作线程直接操作 Tk**。`_start_bar()` 和 `self.webp_mode.get()` 在工作线程里跑，
   主线程不在 mainloop 时直接抛 `RuntimeError: main thread is not in main loop`。
   现在值在主线程取好再传进线程，归零动作走队列派回主线程。
3. **一次界面异常打死整个轮询**。`_poll_queue` 里 `_set_bar` 抛一次异常，`after` 就不再续期，
   之后所有日志和进度全部石沉大海（界面表现为「点了开始，日志一行都不动」）。现在有兜底，
   异常只跳过这一帧。

## 六、实测（本机，1920×1150 工作区）

| 数据 | 帧数 | 旧流程 | 新流程 |
|---|---|---|---|
| 585 KB 随机（2×2 WebP） | 213 → 54 | ~25 秒 | **4.6 秒** |
| 2.5 MB 随机（2×2 WebP） | 900 → 222 | ~90 秒 | **13.7 秒** |
| 16.5 MB rar（估算） | 3823 → 957 | ~300 秒 | **~85 秒** |

16.5MB 剩下的时间几乎全在「排版」：zxing 逐帧编码 3825 张 version-40 二维码，
**单核约 70 秒**，这是库的固定成本（多线程无效，实测 8 线程 0.94 倍）。
想再快只能降帧数：纠错级别从 M 降到 L 能多装 26% 的数据，帧数少两成。

## 八、图标回来了（又丢了一次）

打包命令换成统一脚本之后，`--icon` 和 `--add-data assets` 这两项漏掉了：

- exe 文件本身退回 PyInstaller 默认图标
- 窗口标题栏 / 任务栏图标也没了（`asset_path()` 在包里找不到 `assets/officepack.ico`）

现在两条打包命令（目录版 + 单文件版）都带上了 `--icon` 与 `--add-data`，
并且 `verify_release.py` 加了一项硬校验：**包里没有 `assets/officepack.ico`
或尺寸 PNG 少于 3 张，直接判失败**。这个坑踩过两次，不能再靠记性。

⚠ 注意：`--specpath build` 时，PyInstaller 把 `--icon` / `--add-data` 的**相对路径
按 build 目录解析**，所以要写 `../assets`，写 `assets` 会报
`Unable to find ...\build\assets`。

## 九、升级提示

- 输出文件格式没有任何变化，旧产物照常还原
- WebP 动图仍是**标准格式**，只是合成方式从 libwebp 的封装器换成了手写容器

# v1.4.5 — 框选时任务栏图标不再消失，补录只补缺的帧

四件事：**① 扫描期间任务栏图标一直在**；**② 悬浮条可拖动、可调透明度**；
**③ 补录只补缺的帧、按钮上写明缺几帧**；**④ WebP 能单独导出，合成时间砍一半**。

---

## 一、修的是上一版做过头的地方

上一版为了不让主窗口压住二维码，用了 `withdraw()` 把窗口彻底藏起来 —— 连任务栏图标
一起没了。结果：扫描跑几分钟，这期间你想回来看日志、想点停止、想改个设置，**无从下手**。

现在改成 `iconify()`（最小化）：

| | 旧（v1.4.4） | 现在（v1.4.5） |
|---|---|---|
| 主窗口 | `withdraw()` 彻底隐藏 | `iconify()` 最小化 |
| 任务栏图标 | **消失**，点不回来 | **一直在**，随时点回来 |
| 点回来之后 | 1 秒内又被强行藏掉，等于点不动 | 窗口自动挪到框外，扫描继续 |
| 结束后 | 恢复 | 恢复到**原来的位置**（挪过的会还回去） |

## 二、点回来不会挡住二维码

挪窗逻辑：把扫描区域按 `物理 ÷ 缩放比` 换算成逻辑坐标（Tk 的窗口位置用的是这一套），
然后在每块屏的四个角里找**第一个和框完全不重叠**的位置。只挨着边不算重叠。

- 双屏、码在副屏 → 窗口自动落到主屏角上
- 窗口原本就在框外 → 不动它（尊重你自己摆的位置）
- 最大化状态被点回来 → 先还原再挪，扫描结束后还原成最大化
- 一块屏被框满了实在挤不开 → 日志提示「窗口正压在框选区域上，请拖开或最小化」，
  不再反复挪来挪去

## 三、悬浮条多了「主窗口」按钮

```
正在连拍收帧 · 主窗口在任务栏，点图标可回来
已收 631/978 帧 · 还要 1 分 40 秒     [主窗口] [停止]
```

不想去任务栏找图标，直接点「主窗口」。按钮改成**先 pack**，状态文字再长也挤不掉它们
（以前 pack 顺序反了，文字一长按钮会被压成 0 宽）。

## 三、悬浮条：可以拖、可以调透明度

```
正在连拍收帧 · 按住这里可拖动              透明 ▬▬▬●
已收 631/978 帧 · 还要 1 分 40 秒     [主窗口] [停止]
```

- **拖动**：按住标题或状态文字，拖到哪停哪（按钮上不绑拖动，免得点「停止」时误移）
- **透明度**：右上角滑杆 35%~100%，调淡了不挡视线，仍然看得清进度
- **记住**：位置和透明度存在 `%APPDATA%\OfficePack\hud.json`，下次扫描直接沿用
- 记住的位置如果正好压在框选区域上，会临时换到没被框住的角（不覆盖你存的位置）
- 滑杆松手才写盘，拖动过程中不会每秒写几十次文件

## 四、补录：已收的帧一帧都不重收

上一版虽然记住了上次的区域，但按钮上什么都没写，用户看不出来「点它到底会干什么」，
也分不清它和「重新框选」有什么区别。现在：

| 按钮 | 什么时候用 | 会不会重收 |
|---|---|---|
| **再来一轮（只补缺的 N 帧，不用重框）** | 框没错，只是漏了几帧 | 不会，已收的直接算数 |
| **重新框选（框歪了才用，同样只补缺的 N 帧）** | 框偏了/换了块屏 | 不会，已收的照样留着 |

- 缺帧数直接写进按钮文字（`只补缺的 7 帧`），不用再猜
- 换成**另一份文件**时按段头里的文档 ID 判断，自动把上一份的帧作废，不会串味
- **为什么缺 1 帧也要等一整轮**：缺的那帧可能在第 1 帧也可能在最后一帧，
  只能让动图从头播到尾、见尾帧才敢停。日志会提前写清「这轮约 5 分 30 秒」，
  免得你以为程序在偷懒
- 收多了不再显示 `986/983` 这种自相矛盾的数字（屏幕上同一帧被认成两个文本时会这样）

## 五、WebP：能单独导出，合成时间砍一半

- **单 WebP 导出**：格式下拉里 `WebP 动图` 现在真的**只出 webp**，不写 PNG 也不写 GIF
  （以前会被「一帧就装下 → 回落 PNG」的逻辑偷偷换成 PNG，于是看起来像「没有单 WebP 导出」）。
  单帧文件也会写一张静态 WebP
- **合成提速**：编码档位从 `method=3` 降到 `1`（体积完全一样，时间省两成），
  超过 400 帧再自动降到 `0`（体积大 40%，时间再砍一半）。983 帧实测 78 秒 → 24 秒
- **日志报耗时**：`合成 WebP 用了 24.3 秒（983 帧 · 无损 · method=0，约 24.7 ms/帧）`
- **顺带说明「能不能多线程合成」**：不能。libwebp 的**无损**编码器是单线程的，
  Pillow 的 `threads=` 对无损实测只有 ±5% 的噪声（56 帧：0 线程 1.19s、4 线程 1.19s）。
  真要并行只能自己拼 RIFF/ANMF 容器，代价是丢掉帧间预测（体积涨 1.5 倍以上）＋
  手写容器解析器的风险，不划算。省时间改走另外三条确定有效的路：
  ① 档位自适应；② GIF + WebP 同时要时帧只渲染一遍；③ 只选 WebP 时不再白画一遍 PNG

## 六、日志下面那两道杠

那两条是「文件级进度」和「当前文件内部进度」，以前常驻在日志下方，空闲时就是两条
空白的框 —— 看着像界面坏了。现在**只在有活干的时候出现**，收工自动收起。

顺带修了一个更要命的布局问题：日志区 `expand=True` 会把后 pack 的补录按钮压成 **0 高**
（pack 了却点不到，等于缺帧了但没有补录按钮）。底部固定区改成先 pack，
按钮终于拿得到 27px 的真实高度。

## 七、验证

- 全量单测 **162 项通过**（1 项因当前会话抓不到桌面而跳过），新增 6 项：
  `_overlaps` 边界、`_free_spot` 选角、整屏被框满时返回 None、
  「扫描期间必须是 iconify 而不是 withdraw」的回归断言、
  续收只补缺帧（`fresh ≤ 2`）、WebP 档位自适应、单 WebP 可解码且帧数对得上、
  悬浮条配置往返（含越界夹取与坏 JSON 容错）、空闲时两条进度条都不显示
- 真机验证（本机双屏 1536+1536）：
  - `iconify()` → `state=iconic`，`deiconify()` → `state=normal`
  - 窗口故意压在框上（`+2420+110`）→ 自动挪到 `+8+8`，重叠判定 `False`
  - 扫描结束 → 回到原位置 `+482+87`
  - 悬浮条 400px 可用宽度内：`停止 52 + 主窗口 65 + 状态 277 = 394`，无裁切
  - 补录按钮实测高度 27px（修复前是 1px，`winfo_ismapped()` 返回 0）
  - 空闲 / 处理中 / 收工三态：进度条 `0,0 → 1,1 → 0,0`
  - 单 WebP 导出实测产物：`a.bin.qr.webp`（73.8 KiB），目录里没有 PNG

## 升级建议

**上一版觉得「框选时窗口消失了、什么都干不了」的直接升这个版本。**
用法：框选 → 让它自己跑 → 想看进度就点任务栏图标或悬浮条上的「主窗口」；
缺帧了点「再来一轮」，已收的帧不会重收。
